## 3. GET, POST, PUT, DELETE에 대해 설명해주세요.
각각은 HTTP 메서드의 일부이며 웹 서버에 요청할 때 사용 
- GET 
	- 특정 서버에게 특정 리소스를 요청하는 메서드
	- 요청 데이터는 URL의 쿼리 스트링으로 전달됨
- POST
	- 서버에게 새로운 리소스를 생성하거나 기존 리소스를 수정하라고 요청하는 메서드 
	- 요청 데이터는 HTTP 바디에 담겨 저장됨
- PUT
	- 서버에게 특정 리소스를 전체적으로 교체하거나 생성하라고 요청하는 메서드 
	- 요청 데이터는 HTTP 바디에 담겨 저장됨
- DELETE
	- 서버에게 특정 리소스를 삭제하라고 요청하는 메서드 
	- 요청 데이터는 URL의 쿼리 스트링으로 전달됨

|HTTP 메소드 | 안전 | 멱등 | 캐시 가능 |
| GET | O | O | O |
| POST | X | X | O |
| PUT | X | O | X |
| DELETE | X | O | X|

POST vs PUT

| 항목               | POST                 | PUT                    |
| ---------------- | -------------------- | ---------------------- |
| 역할               | 새 리소스를 생성하거나 작업을 위임  | 리소스를 전체 교체하거나 생성(덮어쓰기) |
| 멱등성 (idempotent) | ❌ (요청할 때마다 다른 결과 가능) | ✅ (여러 번 요청해도 결과 동일)    |
| 리소스 위치 지정        | 클라이언트가 모름 → 서버가 생성   | 클라이언트가 명확히 지정          |
| 예시               | POST /users          | PUT /users/123         |
| 주로 쓰는 상황         | 새로운 게시글 등록, 댓글 추가    | 기존 정보 수정, 덮어쓰기 저장      |


`캐시 가능하다` 
- 서버의 응답을 로컬로 저장하여 재사용 가능하다. 
- PUT와 DELETE는 최신 결과를 받아야 하기 때문에 로컬에 저장하여 재사용할 수 없다. 

`리소스(Resource)란?`
**서버가 식별 가능한 형태로 관리하는 모든 데이터나 기능**
**예시 1: 블로그 웹사이트**
- /posts/1 → 글 1번 (리소스)
- /users/15 → 유저 15번 정보 (리소스)
- /comments → 댓글 목록 (리소스)
각각의 URL은 고유한 **리소스의 위치**이고, 우리가 이 리소스에 대해 GET, POST, PUT, DELETE 같은 HTTP 메서드를 사용하는 거야.

`멱등성이란?`
**요청을 여러번 보내도 서버의 상태가 변하지 않는 특성**
- POST는 동일한 요청을 여러 번 보내면 서버의 상태는 한 번 보낸 것과 다르게 변경될 수 있기 때문에 멱등하지 않다,

## 4. URI, URL, URN에 대해 설명해 주세요. 
- 인터넷에서 **자원**을 **식별**하는 **방식**에 대한 개념 
- uniform resource identifier(uri)
	- 상위 개념 
	- 자원을 식별하는 문자열 
- uniform resource locator(url)
	- 리소스의 위치를 나타내는 문자열 
	- 리소스에 접근하는 프로토콜(http://)을 포함 
	- 가장 구체적이고 명확
- uniform resource name(urn)
	- 자원의 이름을 나타내는 문자열 
	- 특정 명명 체계를 사용 

`url`
https://lee.jun@www.example.com:123/forum/questions/?tag=network

`자원이란?`
- 인터넷 상의 무언가
- 서버에서 관리되는 **데이터나 기능** 주, 고유하게 식별가능한 것 
- 게시글, 유저, 상품, 이미지, 기능(API)
