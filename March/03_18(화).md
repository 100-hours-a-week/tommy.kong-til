## SQL 응용

`view` 
- 데이터 조회를 빠르게 하고 재사용과 유지보수를 용이하게 하기 위해 
- 일종의 가상 테이블을 생성하는 것 -> table을 새로 생성하는 것보다 유지보수하기 유용함. 
```sql
CREATE VIEW 뷰이름 AS
SELECT 출력할컬럼들
FROM 테이블1
JOIN 테이블2
ON 조건문
```

`union`
cf) in python 
- 두 type을 union한 것은 무엇일까?
	- `Union type; Union[X, Y]is equivalent to X | Y and means either X or Y.`
in sql 
- 서로 다른 테이블에서 검색된 결과를 하나의 결과로 결합 
```sql
CREATE VIEW 뷰이름 AS
SELECT 출력할컬럼들
FROM 테이블1
UNION
SELECT 출력할컬럼들
FROM 테이블2
```

## ERD

Relationship
Diagram 
테이블은 객체로 표현 
컬럼은 속성으로 개체 내에 포함되어 표기 
테이블 간의 연결성은 PK와 FK을 통해 나타냄. 

관계라는 것은 총 3가지 
1:1 관계
1:N 관계
N:M 관계 

identifying => 부모가 없으면 존재할 수 없음 -> 부모테이블의 기본 키를 자식테이블의 기본키로 사용
non-identifying => 없어도 존재할 수 있음 -> A가 없어도 B가 존재할 수 있는 관계

```sql
CREATE TABLE Teacher (
    teacher_id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50),
    programming_language VARCHAR(50)
);
```

```sql
CREATE TABLE Course ( course_id INT PRIMARY KEY AUTO_INCREMENT, name VARCHAR(50), teacher_id INT, FOREIGN KEY (teacher_id) REFERENCES Teacher(teacher_id) );
```
- PRIMARY KEY (기본 키): 테이블에서 각 행(row)을 고유하게 식별하는 열(column) 또는 열들의 조합. 중복될 수 없고 NULL 값을 가질 수 없음.
- FOREIGN KEY (참조 키): 다른 테이블의 기본 키(PRIMARY KEY)를 참조하는 키. 데이터 무결성을 유지하는 역할을 함.
- REFERENCES: FOREIGN KEY 제약 조건을 정의할 때 사용되며, 특정 테이블의 특정 열을 참조하도록 설정함.
- AUTO_INCREMENT: 숫자형(INT 등) 기본 키 열에서 자동으로 값을 증가시키는 기능. INSERT 시 값을 명시적으로 입력하지 않아도 자동으로 증가된 값이 할당됨.

## index
인텍스를 배워야하는 이유 
- 데이터를 정렬하면 매우 빠르게 정렬된 결과를 알 수 있기 때문 -> <span style="background:#fff88f">조회</span>
- 인덱스를 정렬하고 서칭하는 방법을 이해하기 위해서는 그전에 tree에 대해 알아야한다. 
	- Tree
	- BST
	- B-tree
	- B+tree
- 인덱스의 종류 
	- 클러스터형 인덱스 
		- 물리적으로 정렬되어 저장되는 인덱스
	- 비클러스터형 인덱스 
		- 물리적으로 분리되어 인덱스가 별도의 테이블에 저장되어 있는 형태 
		- 테이블에는 원본 데이터 위치를 가리키는 포인터만 포함되어 있음
	- 인덱스는 커디널러티(고유성)이 높은 것이 중요하다.
