## Model Architecture 
<font color="#ff0000">전체 모델의 구조</font>
<span style="background:#fff88f">어떤 문제를 해결할지,</span> 다양한 레이어가 어떻게 결합하여 데이터를 처리하고 결과를 도출하는 지는 구조에 따라 달라진다. 
<font color="#ff0000">더 좋은 구조의 모델을 찾는 것이 우리의 관심사항이다.</font>
- CNN이라는 모델 구조를 왜 쓰는가?
	- 이미지 처리, 분류 -> 2d 정보를 추출하는데 합성곱이 효과가 있기 때문에 사용 

딥러닝 모델의 기본은 학습 과정을 통해 찾아낸 최적 weight들(파라미터들)의 집합이다. 

-> 복잡한 데이터에서 높은 수준의 특징을 자동으로 학습해 weight를 조정하는 것 

**조정하는 데 우리가 결정해야하는 사항들 -> hyperparameter** 

1, **모델 구조 관련 하이퍼파라미터**
	• **뉴런 수 (Number of neurons)**
		• **각 레이어(층)에서 사용할 뉴런(노드)의 개수**를 의미합니다.
		• 너무 많으면 오버피팅(overfitting), 너무 적으면 언더피팅(underfitting) 위험이 있음.
	• **레이어 수 (Number of layers)**
		• 신경망에서 **은닉층(hidden layer)의 개수**를 의미합니다.
		• 딥러닝이 깊어질수록 표현력이 증가하지만, **과적합(overfitting) 가능성이 높아짐**.
	• **활성화 함수 (Activation function)**
		• **ReLU, Sigmoid, Tanh, Leaky ReLU 등 다양한 활성화 함수 중에서 선택**.
			- ReLU
				- $f(x) = max(0,x)$
				- **비선형 함수**로, 딥러닝에서 **은닉층의 활성화 함수로 가장 많이 사용됨**.
				- 계산이 단순하고 **기울기 소실(Vanishing Gradient) 문제를 해결**함.
				- 하지만, x ≤ 0이면 기울기가 0이 되어 뉴런이 죽는 문제(Dead Neuron)가 발생할 수 있음
```python
import numpy as np
import matplotlib.pyplot as plt 

x = np.arange(1,10,0.1)
def relu(x):
	return np.maximum(0,x)
y = relu(x)
plt.plot(x,y)
```
- 
			- Sigmoid
				- $f(x) = \frac{1}{1+e^{-x}}$
				- 입력을 **0과 1 사이의 값으로 변환**하는 **S자(S-shaped) 곡선**
					- 작은 값에서는 0에 가까워 지고, 큰값에서는 1에 가까워짐 
				- 출력이 확률처럼 해석될 수 있어 **이진 분류(Binary Classification)** 문제에서 자주 사용
				- 하지만, **입력값이 너무 크거나 작으면 기울기가 거의 0이 되어 학습이 어려운 문제(Vanishing Gradient)**가 발생
					- 출력값이 0 또는 1에 가까워질수록 경사하강법의 학습 속도가 느려짐.
```python
import numpy as np
import matplotlib.pyplot as plt 

x = np.arange(1,10,0.1)
def sigmoid(x):
	return 1 / (1+np.exp(-x))
y = sigmoid(x)
plt.plot(x,y)
```
- 
			- Tanh
				- $f(x) = \frac{e^x - e^{-x}}{e^x + e^{-x}}$
				- **Sigmoid 함수의 변형**으로, **출력 범위가 -1 ~ 1** 
					- 음수의 입력값도 다룰 수 있어 Sigmoid보다 성능이 좋음
				- 중심이 **0을 기준으로 대칭**이므로 **출력이 평균적으로 0에 가까워지는 효과**가 있음
				- 하지만, **입력값이 너무 크거나 작으면 기울기가 0에 가까워지는 문제(Vanishing Gradient)가 발생**
				- ReLU보다 학습이 어려움
```python
import numpy as np
import matplotlib.pyplot as plt 

x = np.arange(1,10,0.1)
def tanh(x):
	return np.tanh(x)
y = tanh(x)
plt.plot(x,y)
```
- 
			- Leaky ReLU
				- $f(x) = \begin{cases} x, & \text{if } x > 0 \\ \alpha x, & \text{if } x \leq 0 \end{cases}$
				- $\alpha$ 는 주로 작은 양수(보통 0.01)이며, 음수 구간에서 작은 기울기를 유지함. 
					- $x \leq 0$일 때도 기울기 0이 아닌 작은 값을 유지하여 학습이 계속됨(ReLU의 Dead Neuron)문제를 해결 
				- 일반적으로 **ReLU**가 많이 사용됨. -> ReLU보다 안정적인 학습이 가능하지만 하이퍼파라미터 $\alpha$ 값을 조정해야하기 때문 
```python
import numpy as np
import matplotlib.pyplot as plt 

x = np.arange(1,10,0.1)
def leaky_relu(x,alpha = 0.01):
	return np.where(x > 0, x, alpha * x)
y = leaky_relu(x)
plt.plot(x,y)
```
- 실제로 대부분의 딥러닝 모델에서는 ReLU 또는 Leaky ReLU를 사용하고, Sigmoid는 출력층에서 확률을 다룰 때만 사용
	• **드롭아웃 비율 (Dropout rate)**
		• **특정 확률로 뉴런을 무작위로 제거**하여 **오버피팅을 방지**하는 기법.
		• 일반적으로 0.2~0.5 사이로 설정.

1. **학습 과정 관련 하이퍼파라미터**
	• **학습률 (Learning rate, α)**
		• 모델이 **가중치를 업데이트하는 속도를 결정하는 값**.
		• 너무 크면 최적값을 지나칠 위험, 너무 작으면 수렴 속도가 느려짐.
		• 일반적으로 **0.001 ~ 0.01** 사이의 값을 많이 사용함.
	• **배치 크기 (Batch size)** 
		 $$\text{배치 개수} = \frac{\text{전체 데이터 개수(N)}}{\text{배치 크기 (B)}}$$
		- 한 번의 가중치 업데이트(즉, 한 번의 학습 과정)에서 사용되는 데이터 샘플의 개수를 의미
		• **미니배치(Mini-batch) 학습**: 배치 크기: 16, 32, 64, 128 등 (일반적으로 2의 거듭제곱)
		• 가장 일반적으로 사용됨. 학습 속도와 안정성의 균형이 좋음.
		• **큰 배치(128~512)**: 학습이 빠르지만, 메모리 사용량이 많고 일반화 성능이 떨어질 수 있음.
	1. **배치 학습(Batch learning, Full Batch)**:

• 배치 크기 = 전체 데이터셋

• 메모리 사용량이 크지만, 최적화가 안정적일 수 있음.

1. **확률적 경사 하강법(SGD, Stochastic Gradient Descent)**:

• 배치 크기 = 1

• 업데이트가 빠르지만, 변동성이 큼.
	• **에포크 수 (Epochs)** 
		$$\text{총 학습 업데이트 횟수} = \frac{\text{전체 데이터 개수(N)}}{\text{배치 크기(B)}} \times \text{에포크 수(E)}
		= \text{배치 개수} \times \text{에포크 수(E)}
		$$
		• **전체 데이터를 몇 번 반복해서 학습할지를 결정**.
		- **에포크(Epoch)**는 전체 데이터셋을 한 번 모두 학습하는 과정을 의미
		• 너무 많으면 오버피팅, 너무 적으면 학습 부족(underfitting) 가능성.
		 - **트레이드오프**: 배치 크기와 에포크 수의 조절이 모델 성능과 학습 속도에 영향을 줌.
		- **1 에포크 = (전체 데이터 수) ÷ (배치 크기) 만큼의 가중치 업데이트 횟수**
		- 학습에 있어서 validation and test
			- validation 
				- 훈련중(epoch마다) 평가하여, 모델이 잘 학습하고 있는 지 확인
				- 과적합 여부를 모니터링하고, 최적의 하이퍼파라미터를 조정
				- 일반적으로 훈련 데이터에서 일부를 떼어내어 사용 
```python
for epoch in range(num_epochs):
    model.train()  # 학습 모드
    for batch in train_loader:
        optimizer.zero_grad()
        output = model(batch)
        loss = criterion(output, batch.labels)
        loss.backward()
        optimizer.step()

    # Validation 평가
    model.eval()  # 평가 모드 (Dropout 비활성화)
    with torch.no_grad():  # 기울기 업데이트 방지
        val_loss = 0
        for batch in val_loader:
            output = model(batch)
            val_loss += criterion(output, batch.labels).item()
    print(f"Epoch {epoch+1}, Validation Loss: {val_loss / len(val_loader)}")
```
			- test
				- 훈련이 끝난 후 최종적으로 모델의 일반화 성능을 평가하는 데이터셋
				- 모델이 완전히 새로운 데이터에서 성능이 어떤지 확인하는 것이 목적 
				- validation 데이터와 달리 모델 튜닝에 전혀 사용되지 않음
```python
model.eval()  # 평가 모드
with torch.no_grad():
    test_loss = 0
    for batch in test_loader:
        output = model(batch)
        test_loss += criterion(output, batch.labels).item()
print(f"Final Test Loss: {test_loss / len(test_loader)}")
```
- 즉, Validation은 모델을 튜닝하는 동안 사용하고, Test는 최종 성능을 측정할 때 한 번만 사용합니다
	• **옵티마이저 (Optimizer)**
		• **경사 하강법(Gradient Descent) 기반의 가중치 업데이트 방식**.
	• 대표적인 옵티마이저:
		• **SGD (Stochastic Gradient Descent)**
			- 일부 샘플(미니배치)을 이용해 가중치를 업데이트하는 방법
			- 단순하지만 학습이 불안정할 수 있음
			- Momentum을 추가하면 진동을 줄이고 빠르게 수렴할 수 있음.
```python
import torch
import torch.nn as nn
import torch.optim as optim

# 예제 모델 정의
model = nn.Linear(10, 1)  # 입력 10개, 출력 1개

# 옵티마이저 설정 (SGD)
optimizer = optim.SGD(model.parameters(), lr=0.01, momentum=0.9)

# 가상의 손실(loss) 정의
loss = torch.tensor(1.0, requires_grad=True)

# 역전파 및 가중치 업데이트
optimizer.zero_grad()  # 기울기 초기화
loss.backward()  # 역전파
optimizer.step()  # 가중치 업데이트
```
- Momentu을 왜 사용하는가? 
- 기본 **SGD(SGD without Momentum)**의 단점:

- **진동이 심함** → 데이터가 복잡할수록 학습 경로가 지그재그(zig-zag)로 흔들림.
- **학습 속도가 느림** → 수렴까지 오래 걸림.
- **잘못된 지역 최소값(local minimum)에 갇힐 가능성**이 있음.

🔹 **모멘텀을 추가하면?**

- 과거 업데이트 방향을 반영하여 **진동을 줄이고** 빠르게 수렴 가능.
- 특히, 길쭉한 곡면(loss surface)이 있는 경우 빠르게 방향을 정렬함.
- Momentum 수식
- 모멘텀은 이전 업데이트 방향을 유지하는 방식으로 적용
- $$ \begin{align} v_{t} = \beta v_{t-1} (1-\beta) \nabla L(w_{t}) \\ w_{t+1} = w_{t} - \alpha v_{t} \end{align}$$
- $v_{t}$ : 모멤텀 벡터(이전 기울기를 반영)
- $beta$ : 모멤텀 계수(보통 0.9 사용)
- $\nabla L(w_{t})$ : 현재 손실함수의 기울기
- $\alpha$ : 학습률
- $w_{t}$ : 현재 가중치
- 모멘텀을 적용하면 **이전 기울기 방향을 일정 비율(**\beta**)로 유지**하여, 갑자기 방향이 바뀌는 것을 방지하고 더 부드럽게 이동할 수 있음.
```python
import torch
import torch.nn as nn
import torch.optim as optim

# 예제 모델

model = nn.Linear(10, 1)
# Momentum을 적용한 SGD 옵티마이저
optimizer = optim.SGD(model.parameters(), lr=0.01, momentum=0.9)

# 가상의 손실(loss) 정의
loss = torch.tensor(1.0, requires_grad=True)

# 역전파 및 가중치 업데이트
optimizer.zero_grad()  # 기울기 초기화
loss.backward()  # 역전파
optimizer.step()  # 가중치 업데이트
```
**기울기를 따라가면서도, 이전 움직임을 고려하여 더 부드럽고 빠르게 학습하는 방법**
**1. 왜 Adaptive Learning Rate가 필요할까?**

  

**🛑 기본 SGD의 문제점**

• **고정된 학습률 (Fixed Learning Rate)**

• 너무 크면 발산(Divergence) 가능 📈

• 너무 작으면 수렴 속도가 느려짐 📉

• **모든 가중치가 동일한 학습률을 사용**

• 일부 가중치는 빠르게 학습될 필요가 있지만, 일부는 천천히 조정되어야 함.

  

✅ **Adaptive Learning Rate 기법은 학습률을 자동으로 조절하여 이러한 문제를 해결**할 수 있음.
		• **Adam** (가장 많이 사용됨)
			- Momentum과 Adaptive Learning Rate를 결합한 방식 
			- 각각의 가중치에 대해 개별적인 학습률을 조정함 
			- 빠르고 안정적인 수렴을 보이며, 가장 많이 사용되는 옵티마이저 
			- 메모리 사용량이 증가하고, 특정 문제에 과적합 가능
```python
# 옵티마이저 설정 (Adam)
optimizer = optim.Adam(model.parameters(), lr=0.001)

# 가중치 업데이트 과정 동일
optimizer.zero_grad()
loss.backward()
optimizer.step()
```
		• **RMSprop**
			- AdaGrad의 단점을 보완한 방식으로, **최근 기울기 크기의 평균을 사용하여 학습률을 조정**.
			- 학습 속도를 일정하게 유지하면서 빠르게 수렴하는 특징이 있음
			- 순환 신경망에 효과적 but 하이퍼파라미터 튜닝이 필요 
```python
# 옵티마이저 설정 (RMSprop)
optimizer = optim.RMSprop(model.parameters(), lr=0.01, alpha=0.99)

# 가중치 업데이트 과정 동일
optimizer.zero_grad()
loss.backward()
optimizer.step()
```
-  일반적으로 Adam이 가장 많이 사용되며, 특정한 경우(SGD는 일반화 성능이 중요한 경우, RMSprop은 RNN)에서는 다른 옵티마이저를 선택
	• **손실 함수 (Loss fnction)**
		• 모델이 얼마나 잘못 예측했는지를 측정하는 함수.
		• 회귀 문제: MSE(Mean Squared Error)
		• 분류 문제: Cross-Entropy Loss

 **하이퍼파라미터 튜닝 방법**
	**Grid Search**: 여러 조합을 시도하여 최적값을 찾음 (비효율적이지만 체계적).
		- 
	**Random Search**: 임의의 값을 시도하여 최적값을 찾음 (빠르지만 최적값을 놓칠 수도 있음).

	**Bayesian Optimization**: 이전 시도의 결과를 반영하여 최적화.
		- 
	**Hyperband / BOHB**: 적응적으로 성능이 낮은 모델을 조기 종료하여 효율적인 탐색 수행.

## Transfer Learning 
사전 훈련된 모델을 그대로 사용하거나 추가 튜닝하여 새로운 문제에 적용함으로써 학습 시간을 단축하고 성능을 향상시키는 머신러닝 기법 

새로운 문제 : 새로운 기준, 새로운 데이터 

어떤 자신의 문제 : 현존 가장 좋은 모델 찾기
